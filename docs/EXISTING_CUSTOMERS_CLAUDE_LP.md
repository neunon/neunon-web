## 2. 何を見て作ったか

- **実際の納品物**（竹本容器様向け 顧客企業クローズアップ ver1／ver2）を PowerPoint で画像化して確認。
  型は「1社3枚：会社概要／商品ラインナップ／提案・連携余地」、大口顧客は組織図・ブランド別推移を足して10枚前後。
  書式は Arial＋ＭＳ Ｐゴシック、灰色の見出し箱、青灰の積み上げグラフ、示唆は赤字、右上に分量の札、左下に出所。
- **核心の発見**：分析は顧客企業を「依頼元の商材との接点」から読んでいる（容器メーカーなら容器接点）。
  一般的な企業データベースとの違いはここにあり、LPの訴求軸にした。
- **パッケージ型支援事業_提案書**（2026/10/20）：価格・分量・納期の目安・お試し可・実績。
- **公開中のパッケージ型支援ページ**（`content/services/02-package.json`）：依頼の流れ、体制、FAQの既存回答。

顧客固有の情報（竹本容器様、およびその取引先の分析）は一切公開していない。

## 3. サンプルレポート（架空）

実在企業を使わず、**架空企業「ミオリ食品株式会社」**を、架空の**低温物流会社**が依頼した設定で、
実物と同じ型・同じ情報密度の Standard（5ページ）を新規制作した。
「ミオリ食品」は検索で実在の同名企業が見当たらないことを確認したうえで採用。全ページに「架空サンプル」の札と注記がある。

| ページ | 内容 |
|---|---|
| (1) 会社概要 | 事業別売上の積み上げ（ネイティブのグラフ）、営業利益、従業員、特徴・強み、顧客・販売チャネル |
| (2) 商品ラインナップ | 4カテゴリの商品・価格帯・温度帯・販路、物流との接点の評価帯、商品図 |
| (3) 直近の動向 | 2024〜2026年の出来事5件の時系列と、物流への影響の表 |
| (4) 取引状況の整理 | 商品カテゴリ×物流工程の取引マップ（取引中／他社委託（推定）／新規発生） |
| (5) 提案・連携余地 | 優先度つき仮説3件。【事実】【推察】を区別し、想定規模・初回の打ち手・確認事項・留意点まで |

商品写真は権利上使えないため、架空ブランドのパッケージ図10点を新規に描いた（`illustrations.mjs`）。

**再生成の手順**（Windows＋PowerPoint）:

```bash
node design/existing-customers-sample/illustrations.mjs   # 商品図
py design/existing-customers-sample/build_report.py       # PPTX
# PowerPoint で各スライドを幅2400pxのPNGとPDFに書き出す（字詰めを実物どおりにするため PowerPoint 本体で描画）
node design/existing-customers-sample/prepare_assets.mjs <書き出しフォルダ>   # Web用WebPと切り抜き
```

切り抜きの位置と、LP上の印（①②・番号ピン）はスライド上の寸法（in）から計算している。
レポートの配置を変えたら `prepare_assets.mjs` の切り抜きと `ExistingCustomersLp.tsx` の座標も合わせること。

## 4. 構成と判断

購買検討の順（何が届くか → どう読むか → 中身 → 自社向けか → 他手段との違い → 信頼 → 費用と頼み方 → 疑問 → 相談）。

| 節 | 見せ方 | 判断の理由 |
|---|---|---|
| ヒーロー | 取引マップの実物を机に広げ、「取引中の1区画」「未取引の3区画」を実際のセルに重ねて示す | 1枚で「何が届き、何がわかるか」が伝わる。キャッチコピーだけで埋めない |
| 1社を、こう読み解きます | 4段をそれぞれ違う形で（図＋数字／全幅の時系列／印つきマップ＋読み取り／全幅の提案） | 同じ形の繰り返しを避け、横長の図は全幅で文字が読める大きさにする |
| 納品されるレポート | 5ページのタブ切替、ページは全幅表示、押すと原寸 | 小さなプレビューで済ませない。説明文はHTMLでも出す（SEO・読み上げ） |
| 分析の視点は商材で変わる | 同じ顧客の商品図を並べ、依頼元（物流／包装資材／食品機械）で強調する商品と仮説が変わる | 発見した核心（商材との接点）をそのまま見せる |
| 外注するなら何が違うか | 自分で調べる／企業データベース／Neunon の比較表 | 競合他社名は出さず、手段で比べる。データベースの長所も書く |
| 品質は、レポートの中で確かめられます | 実物の該当行に番号を打ち、【事実】【推察】・確認事項・出所を指す | 抽象的な「品質へのこだわり」を書かない |
| 料金と依頼の流れ | 3プランの参考価格、分量を紙の枚数で、20社の計算例、相談時に伝えること | 見積もり依頼に必要な情報を揃える |
| FAQ・最後の相談 | 7問、見積もり依頼と質問の2導線 | 問い合わせフォームの種別を `?topic=` で選択済みにする |

**配色の規則**：黒（文字・操作）、青灰（実物のグラフと同じ階調）、**赤は示唆だけ**（実物で赤字が提案につながる発見を示すのと同じ意味）。
グラデーション、装飾アイコン、意味のない図形、セクション番号の飾りは使っていない。本文と注記はコントラスト比4.5:1以上。

## 7. 事実の出典と、未確定事項

**公開前に確認が必要なこと**

1. **参考価格を具体額で公開してよいか。** 公開中のサイトは「数千円〜」、提案書は具体額。税込・税別の表記も未確認
2. Light の納期目安が「15枚／週」と枚数単位になっている（他は社数）。表記をそろえるか
3. 支援実績4件と「数百件」をこのLPに載せてよいか（提案書には記載あり）
4. **取引状況の受け渡し方法**（どの粒度で預かるか）と、秘密保持契約の扱い。LPでは「ご共有いただける範囲」とだけ書いた
5. 以前の「化粧品など具体的な業界・商材を例示しない」というご指示と、今回の「抽象ラベルだけの資料は不合格」というご指示が両立しないため、
   **実在しない食品メーカー**で具体性を出した。業界の選び方に問題がないか
6. 提案書の価格表の誤字「Adavanced」（LPでは Advanced と表記）
7. サンプルPDFを公開ページから開けるようにしている（架空なので情報漏えいの心配は小さい）
8. 正式URLへの置き換え方。現行LPは Codex のブランチ（`hp/existing-customers-lp-mobile` など、リモート未登録のものを含む）にあり、`main` には未反映
