## 追加した計測設計（2026-10-29）

ユーザー確認済みの目的は「サイト改善」と「お問い合わせに至った流入経路・広告効果の集計」。最初は次の少数のイベントだけを GA4 に送る。国内で解析が有効なときだけ送信し、停止した訪問者や地域を確認できない訪問者の操作は後から送信しない。

| イベント | 発火条件 | 送る情報 |
| --- | --- | --- |
| `page_view` | 各ページの表示 | ページのパス、形式を検証した `utm_source` / `utm_medium` / `utm_campaign` / `utm_id` |
| `cta_click` | ヘッダー・共通末尾CTA、既存顧客LPの相談／資料請求／サンプルへのリンク | 固定値のボタン種類、配置、サービス文脈 |
| `report_preview` | 既存顧客LPのサンプル資料を拡大 | 固定値のサービス文脈 |
| `form_start` | 企業向け問い合わせフォームに最初にフォーカス | 固定値 `contact`。学生エントリーは対象外 |
| `generate_lead` | 企業向け問い合わせを Worker が受理し、完了画面に遷移 | 固定値のフォーム文脈。GA4 のキーイベントにする候補 |

氏名、メールアドレス、本文、添付、フォームの選択内容、任意の URL クエリ、検索語、レポートのページ名は送らない。`lead_source` は実際の集客経路と誤解されるので使わず、`form_context` とする。URL とリファラーからクエリを除去し、UTM は英数字・ハイフン・アンダースコアの1〜64文字だけを許可する。広告では個人名やメールアドレスをキャンペーン名に使わない。Google 広告のクリックID `gclid` は初期実装では送らず、UTM で集計するため、Google 広告との自動照合は限定的。正確な広告コンバージョン連携や `qualify_lead` は、アカウント設定・法務確認・CRM の段階管理ができてから別途設計する。

GA4 の Web ストリームでは測定機能の強化によるフォームイベントをオフにして、`form_start` の重複を避ける。公開前に GA4 管理画面で `generate_lead` をキーイベントに登録し、テスト用の問い合わせ受理件数と GA4 の件数を照合する。停止を選んだ人や国外の人は GA4 に含まれないので、フォーム受信総数との一致は期待しない。

## 承認済みの公開方針

法務担当者である発注者が以下の3点を承認した。技術的な動作と文面の一致は実装側で確認する。

1. GA4を使う目的は、サイトの改善と、お問い合わせに至った流入経路・広告効果の集計でよいか。
2. 閲覧ページ、問い合わせ完了、ブラウザ・端末情報等がGoogleに送られることを公開文面で説明し、氏名・メール・問い合わせ本文・添付は計測イベントへ入れない方針でよいか。
3. 日本国内では通常計測し、本人がフッターから停止した後の計測を止める方式でよいか。国外・地域不明では当面計測しない。

承認済み文面は下の「国内向け方式を採用する場合の文案」。後半の「採用保留：全面同意方式」は比較用の旧案で、今回の公開には使わない。法務担当者の承認を受け、`app/privacy/page.tsx` を PR #19 で更新した。

## 表示方式の見直し（2026-10-29）

初回訪問時に全員へ大きな同意パネルを出す方式は**採用保留**。下のプレビューは、明示的な事前同意が必要な場合の比較案として残す。Google は GA4 の使用とデータの収集・処理方法の開示を求めるが、全地域・全用途で同じバナーの表示を求めているわけではない。日本の個人情報保護委員会も、Cookie 等の個人関連情報を第三者に提供する際の同意要否は、提供先が個人データとして取得することが想定されるか等によると説明している。

**採用方式**は、国内向けの通常のアクセス解析については画面を遮るバナーを出さず、プライバシーポリシーで GA4 の利用・送信項目・利用目的を明示し、フッターから「アクセス解析の設定」を開ける形。停止を選んだ人について以後の GA4 収集を止め、別経路で追跡し直さない。全体の問い合わせ件数はフォームの受信記録で別途照合できるが、停止した人の流入経路や行動は GA4 に反映されない。現行実装では国外と地域不明の訪問者は計測しない。広告パーソナライズ等を後から導入する場合は別途見直す。

下記の「許可した場合のみ」という全面同意方式の旧案は**公開しない**。

### 国内向け方式を採用する場合の文案（新しい第一候補）

> 当サイトでは、サイトの利用状況の把握、内容と使いやすさの改善、お問い合わせにつながった経路の集計のため、Google LLC が提供する Google アナリティクス 4 を利用します。Google アナリティクスは Cookie 等を使用し、閲覧したページ、サイト内の操作、利用日時、ブラウザ・端末情報、おおよその地域などを収集します。氏名、メールアドレス、お問い合わせ本文、添付ファイルは計測イベントに含めません。Google によるデータの取扱いは、[Google の説明](https://policies.google.com/technologies/partner-sites?hl=ja_JP)をご確認ください。
>
> 日本国内からのアクセスでは、画面下部の「アクセス解析の設定」からいつでも以後の計測を停止・再開できます。停止後はこのサイトから Google アナリティクスへの新たな計測データの送信を止めます。国外からのアクセスについては、地域に応じて計測しないか、必要な同意を取得した場合にのみ計測します。設定にかかわらずサイトの閲覧とお問い合わせフォームは利用できます。

実装時には「利用目的」「業務委託先への提供」の文案も、この方式に合うよう更新する。広告パーソナライズと Google シグナルは初期導入で使用しない。

参考: [Google の開示要件](https://support.google.com/analytics/answer/7318509?hl=ja-JP)、[Google の EU 利用者同意ポリシー](https://www.google.com/about/company/user-consent-policy/)、[個人情報保護委員会の Q&A](https://www.ppc.go.jp/personalinfo/faq/APPI_QA/)。

## 現状と対象

- GA4 の Web ストリーム（測定 ID `G-TLV2CRJH1W`）は作成済み。測定機能の強化はオフ。
- 本番サイトには GA4 / GTM の外部タグがない。PR #19 では GA4 と計測イベントを準備したが、ビルドフラグがオフなら Google には送信しない。
- main の `app/privacy/page.tsx` は解析ツール未使用と明記している。PR #19 で承認済みの文面に更新し、タグの有効化と同じ公開作業で反映する。
- 本案はアクセス解析と広告からの問い合わせ効果の測定を対象とする。広告のパーソナライズ、Google シグナル、広告向けオーディエンス作成は初期導入に含めない。

## 採用保留：全面同意方式のプライバシーポリシー文案

以下は公開用の**文案**。`AGENTS.md` は法務文書の編集をリーガルチェック待ちとしているため、承認前に `app/privacy/page.tsx` を変更しない。

### 「業務委託先への提供」に追加

> アクセス解析に同意された場合、当社は Google LLC が提供する Google アナリティクス 4 を利用します。閲覧・操作に関する情報は Google に送信され、当社の利用状況の分析と広告効果の集計のために処理されます。Google による情報の取扱いは、[Google の説明](https://policies.google.com/technologies/partner-sites?hl=ja_JP)をご確認ください。

### 「Cookie とアクセス解析」の全文差し替え案

> 当サイトでは、フォームの迷惑送信防止のため Cloudflare Turnstile を利用しています。Turnstile は、利用者が人間か自動プログラムかを判定するために必要な範囲で、ブラウザや端末に関する情報を処理します。

> 利用者がアクセス解析を許可した場合に限り、Google LLC が提供する Google アナリティクス 4 を利用します。Cookie 等を用いて、閲覧したページ、アクセス日時、サイト内の操作、ブラウザ・端末情報、おおよその地域などを収集し、サイトの改善と広告からのお問い合わせの効果測定に利用します。氏名、メールアドレス、お問い合わせ本文、添付ファイルは計測イベントに含めません。
>
> アクセス解析の許可・拒否は任意です。拒否しても、サイトの閲覧やお問い合わせフォームの利用に影響はありません。選択は各ページ下部の「Cookie設定」からいつでも変更できます。Google によるデータの取扱いは、[Google の説明](https://policies.google.com/technologies/partner-sites?hl=ja_JP)をご確認ください。

### 文面レビュー時に確認する点

1. Google LLC への送信と広告効果測定の記載が、会社としての実際の利用目的と合っているか。
2. 広告向け機能を使わない初期方針でよいか。将来リマーケティング等を導入する場合は別途文面と同意の見直しが必要。
3. GA4 側のデータ保持期間・Google アカウントの共有設定を確認し、必要なら保管期間の記載を追加する。
4. アクセス解析に使う URL とイベントに、フォームの入力値や任意の URL パラメータが混入しないことを実装時に確認する。

## 採用保留：全面同意画面の案

初回表示時、画面下部に横長の小さなパネルを出す。白背景、細いグレーの枠、既存サイトの黒いボタンと青いアクセントを使用する。本文を覆い過ぎない高さにし、スマートフォンでは縦積みにする。[静的プレビュー](./ga4-consent-preview.html)を参照。

**表示文**

> サイトの改善と広告からのお問い合わせの効果測定のため、アクセス解析を利用します。許可した場合のみ Google アナリティクスを読み込みます。拒否してもサイトをご利用いただけます。

**操作**

- 「解析を許可する」：同意を保存し、その後に初めて GA4 タグを読み込む。
- 「拒否して続ける」：拒否を保存。GA4 タグを読み込まず、Google への解析データ送信もしない。
- 「詳しく見る」：プライバシーポリシーの「Cookie とアクセス解析」に移動。
- フッターの「Cookie設定」：選択済みの人も設定を開き直せる。撤回後は以後の収集を止める。
- ボタンは同等の視認性にし、許可を初期選択しない。選択が保存できない場合は拒否として扱う。

## 採用保留：全面同意方式を選ぶ場合の確認項目

1. 全ページで初回だけ同意画面を表示。Cloudflare Turnstile、フォーム、CMS 認証は同意に関係なく動かす。
2. 同意前・拒否後には Google の解析スクリプト、Cookie、解析リクエストが発生しないことをブラウザーで検証する。
3. 許可後にだけページビューを送る。フォームの入力値・自由記述・メールアドレスをイベントに含めない。URL パラメータは必要な広告計測用のもの以外を除外する。
4. 問い合わせ完了イベントは Worker が正常受理した後に 1 回だけ送る。過去に同意前に積まれた `dataLayer` イベントを、後からまとめて送らない。
5. GA4 でテスト用のページビューと問い合わせ完了イベントを確認し、広告配信前に計測の一致を確認する。
6. プライバシーポリシーと同意画面の公開は同じリリースで行う。

## 2026-10-29 の実装状況と公開手順

国内向けの停止設定をサイトのフッターに実装した。計測はビルド環境変数 `NEXT_PUBLIC_GA4_ENABLED=true` の場合だけ起動する。現行の本番設定にはまだこの変数を入れない。Worker の `GET /analytics-region` は国コードのみを返し、サイトは `JP` と確認できた場合だけ GA4 を読み込む。国外または地域確認に失敗した場合は読み込まない。停止はブラウザーに保存し、以後の送信を無効化する。再開もフッターから行える。

公開前に必要な作業:

1. 法務担当者の承認済み文面を反映した `app/privacy/page.tsx` を PR #19 から公開する。「解析ツール未使用」という表示が残ったまま GA4 を有効化しない。
2. Cloudflare の `neunon-form-api` Worker を更新し、`https://neun-on.com` から `GET /analytics-region` が国コード `JP` を返すことを確認する。位置情報が不明ならタグは読み込まれない。
3. Render の環境変数に `NEXT_PUBLIC_GA4_MEASUREMENT_ID=G-TLV2CRJH1W`、`NEXT_PUBLIC_ANALYTICS_REGION_ENDPOINT=https://neunon-form-api.keisakamoto.workers.dev/analytics-region`、`NEXT_PUBLIC_GA4_ENABLED=true` を設定して再ビルドする。
4. 本番ブラウザーでページビューと実際のフォーム受理後の `generate_lead` を GA4 の DebugView / リアルタイムで確認する。氏名・メール・本文・URL クエリがイベントに含まれないことを確認する。
5. 「アクセス解析を停止する」後は以後の `collect` リクエストが発生せず、リロード後も停止状態を保つことを確認する。地域判定が失敗した場合も Google タグを読み込まない。

上記は公開作業であり、このブランチでは未実施。プレビュー HTML は古い全面同意パネルの比較用で、フッター設定の実装とは異なる。
